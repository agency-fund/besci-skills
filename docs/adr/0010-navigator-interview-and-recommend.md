# The navigator opens with a choice: an interview, or suggestions straight away

ADR 0009 gave the navigator three modes (conversation, route, guide) and made conversation the default. In use the skill was long, the modes were picked silently so the person could not tell which one they were in, and the first reply to a described problem tended to be an overview of the library. The navigator is most people's first contact with the library, and we want that contact to make them think about their own program before they see a list of skills.

**Two modes, chosen by the person.** When someone describes a problem or asks where to start, the navigator welcomes them, says back what they told it, and offers two ways to begin: think it through together (interview), or go straight to suggestions (recommend). The options are plain text, so the choice works in any tool.

**Two pass-throughs.** A request for one concrete task ("which skill pretests a survey?") gets a recommendation at once, with the interview offered in the closing. A plain question is answered first in a few sentences, as ADR 0009 requires, and then the choice is offered. This replaces ADR 0009's paragraph "Conversation is the default": conversation is no longer a mode of the navigator, only the answer-first rule every skill already carries.

**The interview is a relentless one, adapted from grill-me.** It follows Matt Pocock's grill-me skill (https://github.com/mattpocock/skills, MIT license): one question per turn, each branch settled before the next, and the answer the navigator would lean toward offered with every judgment call. Facts about the program are the person's to give; the navigator does not guess them. There is no question script and no cap. Every five questions or so it gives two lines on what is settled and what is still open, and "wrap up" ends it at any point.

**The catalog stays closed during the interview.** The navigator reads the snapshot only when it compiles, so the questions follow the person's program and not what the library holds. A session that stops early never loads the catalog.

**An interview ends with a brief, then the recommendation.** The brief is short: "What we settled" and "Still open", each open question with what would settle it. The closing offers to save it as a file so the next skill can read it.

**One recommendation template.** It serves both modes and replaces the route and guide templates. For a problem that spans stages the navigator suggests a workflow from the snapshot when one fits, otherwise up to three skills in order, never both and never a longer list, and it says where each suggested skill's evidence has been tested. It drafts a workflow file only when the person asks to save the plan.

**The navigator keeps its own specialist triggers.** They are few, they are raised when they come up, including in the middle of an interview, and the recommendation says which steps the library can support and which need a specialist first.

**The welcome is the navigator's own.** The shared voice block is unchanged for every skill. The navigator's text adds a greeting and defines warmth as attention: saying back what was heard, using the person's words. The rule against praise still holds.

**Consequences.** The catalog snapshot gains a Workflows section and, for each atomic skill, where its evidence has been tested; both are generated by `scripts/snapshot_catalog.py`, and the snapshot job runs when a workflow file changes. The navigator moves to 0.3.0 and no longer declares `produces: workflow-draft`. `CONTEXT.md` defines interview mode, recommend mode, and the brief, and drops conversation as a mode. The navigator's test cases, the README example, and the home-page demo show the new opening. Like ADR 0009, this changes how the library's front door behaves, so it needs agreement from maintainers of both organizations before it is accepted.
